## 项目维护规则

1. **正文事实优先：** 判断V1第01—80章发生过什么，以 `manuscript/01_80.md` 为准；摘要、角色卡和台账不能反向覆盖正文。
2. **历史与重构分离：** V1原件只读保存；V2规划独立迭代，不覆盖V1。
3. **事实与提案分离：** 未经作者批准的方案保持“提案/待裁决”状态，不写成已发生事实。
4. **原始交付只读：** Gemini交付归档后不润色、不覆盖；审查报告由GPT独立撰写。归档不等于验收通过。
5. **单一任务入口：** Gemini等执行模型先阅读 `任务中心/当前任务.md`，再按其指向的任务书执行；不要要求作者复制粘贴整份任务书。
6. **交付闭环：** 全部交付文件直接放入 `inbox/gemini/待交付/` 根目录，不建版本子目录；审查、归档和核验由项目维护流程处理。
7. **同步维护：** 新正文完成后，再同步章节导航、剧情台账、人物状态、时间线和创作路线。
8. **公开仓库安全：** 本仓库当前为Public。不得提交密码、令牌、个人隐私、私人联系方式或其他不应公开的信息；公开前后均需检查新增文件。

## 版本边界

- **已发生事实：** 以正文为准。
- **作者已裁决：** 以作者裁决日志为准，但不得与正文事实冲突。
- **待审规划：** 以相应版本归档和审查报告为准。
- **待作者裁决：** 不得擅自选择方案或写入正式设定。
