## 文件使用规则
1. **版本边界：** V1 正文与 V2 提案分开管理；V2 可以重构 V1 剧情，但不得覆盖 V1 原稿。
2. **正文优先于摘要：** 章节导航、人物卡和剧情台账是辅助资料；冲突时回到对应版本正文核对。
3. **事实与计划分离：** 未经作者批准的方案不得记为已发生事实。
4. **保留历史材料：** 旧版资料不随意删除；新版本使用独立目录和版本号。
5. **交付闭环：** Gemini 文件只投递到 `inbox/gemini/待交付/`；审查后由 GPT 将原件、审查报告和版本索引归档到 `archive/gemini/`。确认归档完整后才清空待交付区。
6. **新增正文后：** 同步章节导航、剧情要素台账、人物状态和创作路线。
7. **隐私：** 仓库包含完整小说正文，建议保持 Private。

## 维护入口
判断“V1 已经发生什么”时，查阅 V1 正文；判断“当前有效设定与人物状态”时，查阅 docs/ 和 characters/；查看尚未批准的 V2 方案时，进入 archive/gemini/ 对应版本目录并核对审查状态。
