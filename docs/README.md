# 仓库导航与维护规则

本页是仓库的文件地图。新增正文、设定或审稿材料时，先按用途归档，避免根目录继续堆积文件。

## 1. 正式入口

| 文件 | 用途 | 当前定位 |
|---|---|---|
| [README.md](../README.md) | 项目总览、当前进度、重要入口 | 仓库首页 |
| [简介.md](../简介.md) | 对外作品简介与核心卖点 | 可继续编辑的简介稿 |
| [创作设定总纲](创作设定总纲.md) | 人物、修炼、世界观和长期方向 | 设定参考；有冲突时需核对更新时间与正文 |
| [剧情要素台账](剧情要素台账.md) | 时间线、人物认知、物件流转、伏笔证据 | 连续性维护表 |
| [70章总目录与剧情摘要](70章总目录与剧情摘要.md) | 第 1—70 章目录与摘要 | 规划稿，不等于完整正文 |
| [前十章时间线核验报告](第一卷前十章时间线核验报告.md) | 已发现的时间锚点与待确认项 | 审稿记录，不直接覆盖正文 |
| [Gemini协作交接书](Gemini协作交接书.md) | 早期模型协作说明 | **旧版材料**；主角姓名、进度可能过时，使用前先核对 README 和正文 |

## 2. 当前正文状态

当前仓库以新版第 1—70 章目录与剧情摘要为唯一剧情规划基线。该文件不是完整章节正文；新版正文尚需按目录补齐。

旧版第 1—30 章工作稿及依赖旧版正文的 Gemini 交接书、前十章时间线核验报告已从当前分支移除，不再作为写作依据。Git 历史仍保留之前提交，可在需要时追溯。

## 3. 归档规则

- 根目录只保留 README、作品简介及必要的仓库配置文件。
- `novel/`：只放按卷、按章编号的正文。
- `docs/`：放设定、剧情台账、目录摘要、审稿报告和协作交接材料。
- 每章一个文件；文件名统一使用中文数字章号与标题，例如 `第十一章-三股之限.md`。
- 不为不存在的章节创建空白正文文件；未完成章节只在目录或进度台账中标注状态。
- 不直接删除旧稿。若新版正文替换旧稿，先保留历史记录，并在变更说明中注明替换依据。
- 设定冲突先登记为“待核对”，不擅自把推测改成正史。
- 文档链接必须指向仓库中的真实文件；禁止用搜索引擎 URL 冒充章节链接。

## 4. 当前整理原则

- 根目录只保留项目首页、作品简介及必要配置。
- `novel/` 只存放当前版本的正式章节正文，按卷归档；未完成章节不创建空文件。
- `docs/` 存放设定、剧情台账、目录摘要和审稿材料。
- 新版正文未完成前，以 `docs/70章总目录与剧情摘要.md` 作为剧情规划入口。
- 不把目录摘要冒充正文；设定总纲和剧情台账须按新版规划逐步复核。
