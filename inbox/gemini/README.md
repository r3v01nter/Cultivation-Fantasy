# Gemini 附件投递区

这里专门存放 Gemini 输出后、等待 ChatGPT 审阅的附件。你可以把 Gemini 生成的正文、人物卡、设定文档、剧情规划、任务报告、核对表以及其他附件原样上传到这个目录。

## 工作流程

1. **Gemini 先投递：** 将生成的文件放在本目录，不要求它直接整理整个仓库。
2. **保留原始输出：** 审阅前尽量保留原文件名和原始内容；不要覆盖正式目录中的文件。
3. **ChatGPT 过目：** 逐份检查内容、与现有正文的冲突、重复文件、格式和适合的归档位置。
4. **给出处理结论：** 明确标注为“可归档”“需修改”“与正文冲突”“重复/旧版”或“待作者裁决”。
5. **确认后再归位：** 只有经过审阅、确认用途后，才将内容整理到 `manuscript/`、`characters/`、`docs/` 或 `docs/planning/` 等正式目录。正文是否纳入正史，以作者确认及正式正文为准。

## 重要规则

- 本目录是**临时收件箱，不是正式资料库**。
- 放在这里的内容默认**不属于正史**，即使文件名写着“定稿”“最终版”也一样。
- 不自动替换正式文件，不因文件内容看似完整就直接并入正文。
- 不在审阅前擅自删除、改写或拆分原始附件。
- 若附件与 `manuscript/01_80.md` 冲突，以现有正文为准，并报告冲突，不自行补写成已发生的事实。
- Word、Markdown、TXT、PDF 等附件可以先放在这里；若 GitHub 无法直接预览某种格式，审阅时再通过上传原附件或转换副本处理，原件保留。
- 文件审阅并完成归档后，可以由作者决定是否清理本目录；不默认自动清空。

## 建议文件命名

可以沿用 Gemini 的原始文件名。若需要区分多轮输出，可加日期或任务编号，例如：

- `2026-10-29_第81-90章正文草稿.md`
- `任务02_人物卡修订稿.docx`
- `任务03_剧情规划与冲突核对.pdf`

**判断原则：先收件、再审阅、后归档；绝不把投递区等同于正史。**
