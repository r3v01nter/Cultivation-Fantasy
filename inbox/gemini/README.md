# Gemini 交付入口

> 本目录只负责接收新一轮交付。已审查的成果统一转入 `archive/gemini/`，不在本目录长期堆放。

## 唯一交付入口

**请将每轮 Gemini 的全部交付文件直接放入：**

`inbox/gemini/待交付/`

不要在本目录根目录新建版本目录，也不要自行判断归档位置。若一次任务包含多个文件，全部放入同一个待交付目录即可。

## 固定处理流程

1. 用户将 Gemini 交付文件放入 `待交付/`。
2. GPT 检查文件完整性、读取内容并进行独立审查。
3. GPT 将本轮原始交付完整归档到 `archive/gemini/对应版本/原始交付/`。
4. GPT 在同一版本归档目录内另存审查报告、版本索引和待裁决事项。
5. 确认归档成功、文件数量和内容校验无误后，才清理 `待交付/`，使其恢复为空置状态。
6. GPT 向用户报告归档位置、审查结论和下一轮任务书。

## 目录规则

- `待交付/`：唯一临时入口，处理完成后保持空置；`.gitkeep` 仅用于让 Git 保留空目录。
- `archive/gemini/`：所有已接收版本的长期归档区。
- 每个版本使用独立目录，至少区分 `原始交付/`、`审查报告.md`、`版本索引.md`。
- 原始交付只搬移，不润色、不覆盖；需要修订时另建新版本文件。
- 未经作者批准的 Gemini 方案和 GPT 建议均为提案，不自动成为正式设定。
- V1 正文、历史版本与已确认的正式设定不得因收件整理而被覆盖。
