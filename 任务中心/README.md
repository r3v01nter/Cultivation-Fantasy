## 固定协作流程

1. ChatGPT根据当前项目状态编写中文任务书，保存为独立的Markdown文件；新版本使用新文件，不覆盖历史任务书。
2. ChatGPT在回复中提供任务书GitHub页面地址和Raw下载地址。
3. 作者将任务书链接或下载文件交给Gemini；Gemini阅读任务书指定的资料并按要求执行。
4. Gemini按任务书规定的文件名、格式和数量生成交付文件，完成自检后整理成一个交付包发送给作者。交付包应有清晰文件名，内部避免无必要的多层目录；同时附文件清单和自检结果。
5. 作者只需接收交付包、解压，并将解压得到的本轮交付文件整体上传到 `inbox/gemini/待交付/`；无需逐份分类、改名或整理，也不需要让Gemini操作GitHub。
6. ChatGPT读取待交付区的全部文件，核对完整性并独立审查；需要返工时发布修订任务。
7. 审查结束后，ChatGPT整理归档原始交付、审查报告和必要索引，核验归档结果，再清理待交付区（仅保留 `.gitkeep`）。
8. ChatGPT根据本轮真实审查结果承接未解决事项，发布下一轮独立Markdown任务书。

## 执行边界

- **Gemini：** 阅读指定资料、执行任务、按要求生成文件、自检、打包并发送给作者。不得要求其写入、提交、清理或归档GitHub仓库。
- **作者：** 接收Gemini交付包，解压后将文件整体提交到待交付区；保留最终裁决权。作者不承担文件分类和仓库归档工作。
- **ChatGPT：** 编写任务书、读取待交付文件、独立审查、整理归档、清理待交付区、维护索引和项目文档。
- 历史任务书不覆盖、不删除；新任务使用新版本文件。
- “已完成”“已交付”“已归档”“审查通过”“作者批准”是不同状态，不得混为一谈。
- 未经作者确认的方案不得写入正式设定或标记为正史。

## 版本承接规则

每轮新任务必须阅读并承接上一轮的原始交付、ChatGPT审查报告、遗留问题、当前有效设定和作者裁决。已通过的内容作为已验证基线，不重复返工；未通过的内容列为修订项；待作者裁决事项不得由Gemini自行决定。正文证据和作者最新裁决优先于旧任务书中的临时结论。
