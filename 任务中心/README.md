## 固定协作流程

1. ChatGPT根据当前项目状态编写中文任务书，保存为独立Markdown文件；新版本使用新文件，不覆盖历史任务书。
2. ChatGPT在回复中提供任务书GitHub页面地址和Raw下载地址。
3. 作者将任务书链接或下载文件交给Gemini；Gemini阅读任务书指定的资料并按要求执行。
4. Gemini按任务书规定的文件名、格式和数量生成交付文件，完成自检后整理成一个交付包发送给作者。
5. 作者只需接收交付包、解压，并将解压得到的本轮交付文件整体上传到 `inbox/gemini/待交付/`；无需逐份分类、改名或整理，也不需要让Gemini操作GitHub。
6. ChatGPT读取待交付区的全部文件，核对完整性并独立审查。
7. 审查结束后，ChatGPT原样归档原始交付、审查报告和版本索引，核验归档后清理待交付区（仅保留 `.gitkeep`）。
8. 根据真实审查结果承接未解决事项，发布下一轮独立Markdown任务书。

## 执行边界

- **Gemini：** 阅读指定资料、执行任务、按要求生成文件、自检、打包并发送给作者。不得要求其操作GitHub。
- **作者：** 接收、解压并整体上传；不承担逐份分类和归档。
- **ChatGPT：** 编写任务书、独立审查、归档、清理待交付区、维护索引和项目文档。
- 历史任务书不覆盖、不删除。
- “已完成”“已交付”“已归档”“审查通过”“作者批准”是不同状态。
- 未经作者确认的方案不得写入正式设定。
